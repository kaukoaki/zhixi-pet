## 历史制作记录：首条待机循环

最初的制作包在 actions/production/00-idle（仅本地制作归档：`../local-assets/notes/00-idle/README.md`），当时使用历史共用角色参考（仅本地制作归档：`../local-assets/references/shared/character-design.png`）与旧提示词。该图保留旧胸标，仅用于溯源；新动作统一使用[当前V5立绘](../assets/character/qiqi-chibi-v5-knot-sprout.png)与新版固定人设和模板（仅本地制作归档：`../local-assets/workshop/docs/animation/README.md`）。下文保留原处理流程，不再要求重新生成已有待机。

在你使用的豆包视频创作入口上传参考图，作为图生视频的起始画面；如果界面提供首帧和尾帧设置，两处使用同一张参考图，有助于首尾回到同姿势。不同账号、版本的入口与参数可能不同，以实际界面为准。这里没有调用火山引擎 API，也不需要你为本项目配置视频 API Key。

首个片段建议约 5 秒、固定镜头、一次轻眨眼、微呼吸和发梢轻摆。保持胸口标志形状，不加入挥手、转身、走动或大特效。普通 MP4 先保留原件；如果没有真实透明通道，需要生成后再进行背景分离与透明转码，不能直接当透明成品导入。

火山引擎公开文档确认 Seedance 系列具有首帧/首尾帧图生视频能力，但它描述的是模型/API，不保证豆包消费端的每个界面都提供相同控制项：[官方能力说明](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)。

## 建议规格

| 项目 | 建议 |
| --- | --- |
| 文件容器 | `.webm`、`.mp4`、`.mov`；内部编码须能被当前 Electron/Chromium 解码 |
| 透明视频 | 优先 WebM，VP9 编码且包含真实 alpha 通道 |
| 不透明视频 | H.264 MP4 兼容性通常较好，但不会透明，也不会自动抠图 |
| 画面比例 | 优先保持当前参考图的 1:1 方形画布；全部动作一致，不裁切人物 |
| 工作分辨率 | 可选时采用 1024 × 1024 或相近方形分辨率；不需要 4K |
| 帧率 | 保留生成模型原生帧率，例如 24 或 30 fps；不要用重复帧冒充 60 fps |
| 单次动作 | 可生成约 5–10 秒，保持进入动作轻快，开头和结尾回到接近待机的姿势 |
| 循环动作 | `idle`、`working` 可生成约 5–10 秒，再按实际画面提取较长的稳定中段；首尾姿势、人物位置与速度连续 |
| 构图 | 全身、固定镜头，脚底基线固定，四周留 8–12% 余量 |
| 声音 | 默认静音，不依赖台词音轨传达信息 |

容器扩展名不能保证兼容性。尤其 `.mov` 可能包含 Electron 无法解码的编码，导入后应先预览。视频即使标称“透明”，也可能只是带棋盘格或纯色背景：只有文件真实包含 alpha 通道，桌面才会透出来。

应用不负责从普通视频中去除背景。不要把绿幕、棋盘格或白底直接当作透明成品。

## 导入流程

1. 打开桌宠面板中的动作管理。
2. 选择对应动作槽并导入视频文件。
3. 在桌宠上预览，检查透明边缘、人物大小、脚底位置、播放流畅度和首尾衔接。默认待机请导入「默认待机」栏，而非其他动作槽。
4. 需要调整时，重新导入修订版。

导入会把文件复制到 `%APPDATA%\QiqiCodexPet` 下的应用媒体库，原始文件保持不变。播放时默认静音；单次动作结束返回默认待机视频（未配置时显示原画待机），`working` 在对应状态下循环。视频层和原画层采用同样的居中缩放；视频本身仍必须保持同一构图，才能避免跳位。空槽保留待机角色。

## 角色一致性基础提示词

后续动作同时参考 [角色动画演出原则](ANIMATION-DIRECTION.md)：保持人设和构图，让眼神、眉眼嘴角、手势与发梢跟随共同表现情绪。通过连续的小情绪推进和柔软起落增加日系 Q 版的可爱与灵动，避免长时间固定同一表情或重复同一大动作。完整示例见 小小困惑提示词（仅本地制作归档：`../local-assets/prompts/06-error/prompt.txt`）。

使用当前栖栖的角色截图作为图生视频参考，并在每个动作中保留以下设定。以下文字是制作模板，不代表项目已调用视频生成模型：

```text
同一位二次元 Q 版桌面伙伴“栖栖 Qiqi”，完整全身，银白长发、
发尾浅青色渐变、右侧编发系黑色蝴蝶结、紫色眼睛、
黑白金配色连衣裙、黑色短披肩与金色藤叶刺绣、黑色短靴，
胸口白色布片上的金色 GPT / OpenAI 六环交织结形标志完整清晰。
严格保持输入角色图的脸型、发型、服装结构、配色与身体比例。
可爱清爽的二次元画风，线条清晰，柔和色块，细节适合桌面小尺寸观看。
固定正面镜头，全身始终完整位于画面内，脚底位置不漂移，
人物主体大小稳定，光线稳定。保持纯色背景，不生成环境或地面阴影。
动作：[填写本次动作要求]。
时长：[填写不超过15秒的时长，优先5–10秒]。使用视频工具提供的原生帧率。
开头从轻松站立姿势开始，结尾自然回到相近姿势。
不生成长句字幕或新增水印；按动作需要允许问号、爱心、zZ 等短符号和小漫画气泡。
不要镜头移动、切镜、额外角色、额外肢体、
服装变化、发色变化、突然变形、背景场景或闪烁光效。
```

如果所用模型不能直接输出透明视频，先在你的制作流程中完成背景分离，再编码为包含 alpha 的 WebM。仅在提示词里写“透明”不会让普通 MP4 获得透明通道。

漫画符号和气泡应有清楚的实色轮廓，放在人物旁的画布空白处，避免盖脸或超出安全边界。处理透明背景时保留这些设计元素；本地脚本默认只保留最大连通人物，已增加可重复的 `--keep-region X,Y,W,H` 参数，用像素坐标指定经过检查的前景区域，保留完整落在区域内的气泡、字符和尾巴，而非保留整块背景。区域需按实际成片选择，避免包含水印。打盹成片使用 `--keep-region 480,20,225,240`。完整演出示例见 打个盹提示词（仅本地制作归档：`../local-assets/prompts/07-sleep/prompt.txt`） 和 欢迎回来提示词（仅本地制作归档：`../local-assets/prompts/08-return/prompt.txt`）。

## 动作增量提示词

将下表内容替换到基础提示词中的 `[填写本次动作要求]`，每次只制作一个动作。

| 槽位 | 动作描述建议 |
| --- | --- |
| `greeting` | 小幅抬手挥两次，温和微笑，手自然放下，身体保持稳定 |
| `drag` | 身体轻轻缩起，双手稍稍张开保持平衡，露出短暂惊讶表情，不位移出画面 |
| `thinking` | 一只手轻触下巴，视线微微上移，眨眼后恢复正面 |
| `working` | 双手轻敲腰部前方的小型悬浮键盘，低于胸口标志；身体稳定，从中段提取自然循环，见 04-working 制作包 |
| `success` | 眼睛亮起，轻轻握拳，露出开心表情，再回到站姿 |
| `error` | 轻微歪头并露出困惑神情，随后温和地点头，不哭泣或夸张摔倒 |
| `sleep` | 小小打哈欠，双手靠近脸侧，短暂闭眼，再自然睁眼站稳 |
| `return` | 从正面站姿轻轻伸展并点头，像重新回到桌面，不做入画或出画位移 |
| `focus` | 深呼吸后点头，收起笑容进入温和专注的神情，最后恢复站姿 |
| `celebrate` | 双手小幅举起庆祝，肩膀轻轻跃动一次，不使用大型粒子或背景变化 |

`working` 的结尾请额外指定“最后一帧与第一帧的姿势、光线、人物位置完全一致，运动速度平滑衔接”。其他动作建议留出短暂的首尾缓冲，以减少与待机之间的跳变。

## 交付前检查

- 与当前角色参考图比较，确认银白长发与青色发尾、编发蝴蝶结、紫色眼睛、胸口徽记和披风都还在。
- 在深色与浅色桌面上检查头发和披风边缘，避免白边、黑边与残留背景。白发在浅色桌面上尤其容易出现抠图残边。
- 确认没有画外肢体、突变、镜头缩放、脚底漂移和首尾闪帧。
- 用应用实际预览确认编码可解码；导入成功不等于每一种编码都可播放。
